  IMPORTANT NOTES
================================================================================

1. DATABASE MIGRATIONS ARE CRITICAL
   → App won't work without migrations executed
   → Must run all 5 scripts in Supabase SQL Editor
   → Tables must show in Table Editor with RLS enabled

2. EMAIL CONFIRMATION REQUIRED
   → Users must confirm email after signup
   → Before confirmation, RLS policies block access
   → Check spam folder for confirmation email
   → Can skip in dev: Supabase dashboard → Auth → Settings

3. RLS POLICIES ARE ENFORCED AT DATABASE LAYER
   → Cannot be bypassed by client code
   → Patients can only see their own data
   → Different roles have different access levels
   → This is a security feature, not a limitation

4. MIGRATION IS CODE-BREAKING
   → Old function calls won't work anymore
   → Must update all files using old db.ts
   → Follow SUPABASE_IMPLEMENTATION.md checklist
   → Test thoroughly before deployment

5. SESSION MANAGEMENT IS AUTOMATIC
   → Middleware refreshes expired tokens
   → Users stay logged in until logout
   → Cookies stored securely (HTTP-only)
   → No need to manually manage tokens
